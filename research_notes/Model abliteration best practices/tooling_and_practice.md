# Practitioner tooling and real-world practice of abliterating open-weight LLMs

Scope: a literature/tooling review of publicly documented refusal-direction-ablation ("abliteration") methods and tools, covering dense, MoE, reasoning, multimodal, and quantized models. Research date 2026-10-14. Primary material: tool source code and READMEs (read from raw GitHub), Hugging Face model cards, author blogs, and arXiv abstract pages. "Self-reported" = the tool's or model's own author; "independent" = a third party. This is a meta-level survey of how the technique and its tooling work and perform; it does not reproduce example harmful content from the sources.

## Key question 1 — Key tools: approaches, defaults, hyperparameters, reported results

### Takeaway
Practice moved from manual, notebook-style single-direction ablation (FailSpy, Labonne, Sumandora, 2024) to automated multi-objective search. Heretic (p-e-w, first public release Nov 2025) is the dominant 2025–2026 tool: an Optuna TPE optimizer co-minimizes a keyword-based refusal count and first-token KL divergence over a parametrized per-component layer-weight kernel. Abliterix is a close fork/competitor adding MoE-specific mechanisms. Independent 2026 benchmarks (Abliterlitics) generally rank Heretic best or near-best for capability retention per unit of refusal removal.

### Cited Findings

**Foundational method (Arditi et al. 2024) — the defaults every tool inherits**
- Training data: 128 harmful instructions sampled from AdvBench, MaliciousInstruct, and TDC2023; 128 harmless from Alpaca; validation 32 harmful (HarmBench val "standard behaviors") + 32 harmless (Alpaca). Candidate directions are difference-in-means vectors computed at every post-instruction token position × every layer — [Arditi et al., arXiv 2406.11717](https://arxiv.org/html/2406.11717)
- Direction selection: minimize a bypass score on harmful-val; require an induce score > 0 and KL < 0.1 on harmless-val; restrict to layers l < 0.8L (keep away from final layers near the unembedding). Weight orthogonalization `W_out' = W_out − r̂ r̂ᵀ W_out` applied to embedding, positional-embedding, attention-out and MLP-out matrices plus output biases — [arXiv 2406.11717](https://arxiv.org/html/2406.11717)
- Reported capability retention (orthogonalized vs baseline), e.g. Llama-3 70B: MMLU 79.8/79.9, GSM8K 90.8/91.2, TruthfulQA 59.5/61.8; Gemma 7B TruthfulQA 44.7/47.1. TruthfulQA consistently drops (−1.0 to −3.5 pts); most other metrics within 99% CIs of baseline — [arXiv 2406.11717](https://arxiv.org/html/2406.11717)

**FailSpy "abliterator" library (2024, TransformerLens-based)**
- A thin TransformerLens wrapper: caches activations over N samples (example `N=512`), computes `refusal_dirs()` as difference-of-means per residual hook, provides `test_dir`, `find_best_refusal_dir`, `apply_refusal_dirs`. Default activation layers `['resid_pre','resid_mid','resid_post']`; author recommends blacklisting the first and last couple of layers because they "will have dramatic effects on outputs." Uses positive/negative "token of interest" presets (e.g. tokens for "Sure" vs "cannot" in Llama-3) to score directions — [FailSpy/abliterator README](https://github.com/FailSpy/abliterator)
- The published 70B model card (Llama-3-70B-Instruct-abliterated-v3.5) notes that the refined v3.5 method modified only a single layer, which "completely eliminated moralizing disclaimers," and warns the model may still "lecture you about ethics/safety." Author frames ablation as far more data-efficient and surgical than fine-tuning, and suggests orthogonalize→fine-tune as a pipeline — [failspy model card](https://huggingface.co/failspy/Meta-Llama-3-70B-Instruct-abliterated-v3.5)

**Maxime Labonne "Uncensor any LLM with abliteration" (blog, 13 Jun 2024)**
- Model: Daredevil-8B (chosen for top MMLU among 8B merges), loaded under the Llama-3-8B name for TransformerLens. Datasets: `mlabonne/harmful_behaviors` (from llm-attacks) and `mlabonne/harmless_alpaca`. `n_inst_train = min(256, …)` (capped at 256/class for RAM); activation batch size 32; evaluation on only 4 test instructions, 64-token generations. Token position: last token (`pos=-1`). Directions computed layers 1..n for resid_pre/mid/post; scoring on resid_pre; top 20 candidates tested; selection was manual (keep candidates whose outputs lack "I cannot/I can't"); layer-9 candidate chosen — [mlabonne blog](https://huggingface.co/blog/mlabonne/abliteration)
- Stated failure modes: abliteration degraded all benchmarks; SFT is brittle on Llama-3-8B so DPO was used for healing; GSM8K did not recover (dataset may need more math); layer selection needs human judgment — [mlabonne blog](https://huggingface.co/blog/mlabonne/abliteration)
- DPO "healing" → NeuralDaredevil-8B-abliterated: DPO via LazyAxolotl/QLoRA 4-bit on `mlabonne/orpo-dpo-mix-40k`; lora_r 64, lora_alpha 32, dropout 0.05, lr 5e-6 cosine, paged_adamw_8bit, 100 warmup, 1 epoch, seq_len 2048, micro-batch 1, grad-accum 8, ZeRO-2; 6×A6000 ≈ 6h45. Nous-suite average recovered to 55.87 (equal to pre-abliteration Daredevil-8B 55.87; abliterated-only was 55.06) — [NeuralDaredevil card](https://huggingface.co/mlabonne/NeuralDaredevil-8B-abliterated)
- Labonne v2 technique (2025, e.g. gemma-3-12b-it-abliterated-v2): weights per layer follow a normal distribution with a tunable spread and peak layer (non-constant kernel — a precursor to Heretic's kernel idea); modules orthogonalized iteratively or via accumulated direction to save memory; hybrid evaluation combining a keyword dictionary and the `NousResearch/Minos-v1` refusal classifier, targeting >90% acceptance while staying coherent. Recommends temperature 1.0, top_k 64, top_p 0.95 for Gemma 3 — [gemma-3-12b-it-abliterated-v2 card](https://huggingface.co/mlabonne/gemma-3-12b-it-abliterated-v2)

**Sumandora "remove-refusals-with-transformers" (2024, plain HF Transformers)**
- Proof-of-concept without TransformerLens; supports most HF models (some custom Qwen layouts need `model.transformer.h` not `model.model.layers`). Defaults in `compute_refusal_dir.py`: `instructions=32`, `layer_idx = int(len(layers)*0.6)`, `pos=-1`, reads `harmful.txt`/`harmless.txt` (AdvBench harmful_behaviors + alpaca-cleaned), generates 1 token with `output_hidden_states`; direction = mean(harmful_hidden) − mean(harmless_hidden) at the chosen layer; applies chat template with `add_generation_prompt=True`. Quantization can be mixed (bnb 4-bit) — [Sumandora README](https://github.com/Sumandora/remove-refusals-with-transformers)
- This is the engine behind most huihui-ai abliterated models (their cards cite it directly).

**jim-plus/llm-abliteration (Jim Lai "grimjim", 2025)**
- Descended from Sumandora; measures the equivalent of resid_post via `hidden_states`. Workflow: `measure.py` → `analyze.py` (chart by layer; "look toward middle to late-middle layers") → craft a YAML describing per-destination-layer strategies and possibly multiple source layers → `sharded_ablate.py` (loads one safetensors shard at a time; at most one layer ablated in VRAM, so very large models fit). Flags: `--projected` (orthogonalize refusal direction vs harmless during measurement), `--normpreserve` (preserve weight row norms), `--invert` (addition instead of ablation), `--deccp` (add CCP-sensitive topics for Chinese models). bnb 4-bit for measurement, but ablation must run on full-weight models. Reported-tested on Llama-3.2, Qwen2.5-Coder, Ministral-8b, Mistral-7B-v0.2, gemma-3-27b-it, Mistral-Nemo; MoE support contributed by @AesSedai, Apple Metal by @otarkhan. Card warns "refusal direction is diffuse," so ablation does not guarantee full removal — [jim-plus/llm-abliteration README](https://github.com/jim-plus/llm-abliteration)

**grimjim's geometric refinements (blogs, the math Heretic builds on)**
- Projected abliteration (25 Oct 2025): ablate only `r_proj = r − (r·μ_A)μ_A` (remove the component parallel to the harmless mean), because refusal entangles a "harmfulness" direction and a "push-away-from-compliance" direction. On Gemma-3-12B, refusal direction had positive cosine with the harmful direction and negative cosine with the harmless direction. Recommends float32 intermediate math, winsorizing activations at 0.995 for Gemma 3 (not needed for Mistral-Nemo), and measuring directions at Gemma layers 23 and 29 (of 48) applied to layer ranges 11–23 and 24–41. Measuring on a 4-bit quant worked and transferred to bf16 — [grimjim projected-abliteration](https://huggingface.co/blog/grimjim/projected-abliteration)
- Norm-preserving biprojected abliteration (6 Nov 2025): after subtracting the directional component of each weight row, restore the original row L2 norms (still rank-1). On Gemma-3-12B UGI leaderboard: baseline UGI 19.58 / NatInt 18.72; standard abliterated 32.08 / 18.64; norm-preserved biprojected 32.61 / 21.33. Lessons: biprojection alone let refusals return (attributed to the "Hydra effect" where other layers compensate), so intervene across a band of layers; per-layer directions underperformed chunk-of-layers; bf16 intermediates gave suboptimal results — [grimjim norm-preserving](https://huggingface.co/blog/grimjim/norm-preserving-biprojected-abliteration)

**Heretic (p-e-w) — the leading automated tool**
- Releases (PyPI `heretic-llm`): 1.0.0/1.0.1 (16 Nov 2025, first public), 1.1.0 (10 Dec 2025), 1.2.0 (14 Feb 2026), 1.3.0 (5 May 2026), 1.4.0 (14 Jun 2026); dev version 2.0.0.dev0 in the repo as of Oct 2026 — [PyPI], [heretic releases](https://github.com/p-e-w/heretic/releases)
- Approach: parametrized directional ablation. Residual directions computed per layer as difference-of-means of the first generated token's residual (position −1 at end of prompt) between harmful and harmless prompts. Orthogonalizes attention out-projection and MLP down-projection. Optuna TPE (multivariate, n_trials=100 with 30 random startup trials) co-minimizes two objectives: a keyword refusal rate and first-token KL divergence (log-softmax, `kl_div` with `reduction="batchmean"`), both measured on 100 held-out prompts — [heretic README](https://github.com/p-e-w/heretic), config defaults below
- Default datasets (config.default.toml): refusal/KeywordRate on `mlabonne/harmful_behaviors` test[:100]; KL on `mlabonne/harmless_alpaca` test[:100]; direction computation uses `train[:400]` from each. KeywordRate markers include "sorry," "i cannot," "as an ai," "disclaimer," "illegal," "unethical," etc. System prompt "You are a helpful assistant." max_response_length 100 tokens — [heretic config.default.toml](https://github.com/p-e-w/heretic/blob/master/config.default.toml)
- Optimizable parameters (classic Abliteration modifier): `direction_scope` ∈ {global, per layer}; `direction_index` is a float in [0.4·L, 0.9·L] (non-integer indices linearly interpolate between the two nearest layer directions — a Heretic innovation); per-component kernel {max_weight, max_weight_position, min_weight, min_weight_distance}. max_weight range is [0.8,1.5] for attention but [−0.25,1.5] clamped at 0 for MLP (so the optimizer can switch MLP ablation fully off); max_weight_position ∈ [0.6·L,1.0·L]. MLP ablation "is often unnecessary for removing refusals and tends to damage model intelligence more than ablating the attention output" (issue #202) — [heretic abliteration.py](https://github.com/p-e-w/heretic/blob/master/src/heretic/modifiers/abliteration.py)
- Implemented as a rank-1 LoRA delta `ΔW = −λ·v·(vᵀW)` (lora_B=−λv, lora_A=vᵀW); `orthogonalize_direction=true` (projected abliteration), `row_normalization` ∈ {none, pre, full} with `full_normalization_lora_rank=3` (MPOA, added v1.2.0 PR #52), optional `winsorization_quantile` to tame "massive activations" — [heretic config / abliteration.py]
- Self-reported headline (Gemma-3-12B): original refuses 97/100. mlabonne-v2 3/100 at KL 1.04; huihui 3/100 at KL 0.45; Heretic 3/100 at KL 0.16 (same refusal suppression, lower capability damage). gpt-oss-20b-heretic v1.0.0 card: 58/100 refusals (down from 100) at KL 0.96, direction_index 16.66, attn.o_proj max_weight 1.44, mlp.down_proj max_weight 1.03 — [heretic README](https://github.com/p-e-w/heretic), [gpt-oss-20b-heretic card](https://huggingface.co/p-e-w/gpt-oss-20b-heretic)
- Runtime: on RTX 3090, default config, Qwen3-4B ≈ 20–30 min; benchmarks batch size at startup. bnb 4-bit via `quantization="bnb_4bit"`. "Well over 5000" community models tagged `heretic` on HF (self-reported) — [heretic README](https://github.com/p-e-w/heretic)
- ARA (Arbitrary-Rank Ablation), Weidmann 2026 (PR #211 opened 4 Mar 2026, merged as plugin via #446 Sep 2026; default modifier in 2.0.0.dev). No refusal direction at all: capture per-module I/O with hooks, optimize a LoRA (default `lora_rank=50`) via L-BFGS (5 outer steps, lr 1.0, 20 inner iters) to a 3-term objective — keep good-prompt outputs unchanged, pull bad-prompt outputs toward good via k-NN (neighbor_count 1..15), and push bad outputs away from their originals (an "overcorrect" term, weight 0..1.3, for "stronger steering that can overcome more complex refusal mechanisms"). Optimizes a layer band [start∈0..L/2, end∈L/2+1..L]. `preserve_row_magnitudes=true` by default. Converges in ~2–3 iterations; reproducible — [heretic ARA source](https://github.com/p-e-w/heretic/blob/master/src/heretic/modifiers/ara.py), [PR #211](https://github.com/p-e-w/heretic/pull/211)

**Abliterix (wuwangzhang1216) — Optuna fork with explicit MoE mechanisms (2026)**
- Same TPE refusal+KL objective as Heretic; adds 150+ prebuilt configs; supports dense, MoE, SSM/hybrid, VLM. Steering methods selectable: mean-difference, PCA, SRA, SAE, SOM, optimal transport, RDO. Edits apply via reversible LoRA adapters, direct weight projection, or runtime hooks. Reproducibility manifests (schema v2) with weight SHA256. Self-reported, e.g. Gemma-4-E4B 7/100 refusals at KL 0.0006; gpt-oss-20b 6/100 at KL 0.0098; Qwen3.6-35B-A3B 7/100 at KL 0.0189 — [abliterix README](https://github.com/wuwangzhang1216/abliterix)
- Self-reported "broken defenses": applied a lerp-then-abliterate recipe (SVD-diagnose a rank-16 LoRA delta, lerp it away at λ=0, then single-direction direct abliteration) against DeepRefusal (EMNLP 2025) and Circuit-Breakers/RR (NeurIPS 2024): e.g. Mistral-7B-RR 12/100 refusals at KL 0.042, 88% ASR under their LLM judge — [abliterix README](https://github.com/wuwangzhang1216/abliterix)

**Other tools named by the community**
- OBLITERATUS (elder-plinius, ~Jul 2026): Gradio/Colab, extraction via PCA / mean-diff / SAE / whitened SVD; "informed" mode auto-configures from analysis of refusal geometry; claims norm-preserving excision. Flagged by the Abliterlitics benchmark as high-KL / capability-destroying in practice (see Q5) — [OBLITERATUS README](https://github.com/elder-plinius/OBLITERATUS)
- Older/reference tools listed by Heretic as prior art: wassname/abliterator, Tsadoq/ErisForge, AUGMXNT/deccp, Orion-zhen/abliteration, huihui-ai — [heretic README](https://github.com/p-e-w/heretic)

### Inferences
- The strong convergence across tools on "difference-of-means at the last prompt token, direction taken from a layer ~40–90% deep, intervene on attention-out and/or MLP-down" reflects direct inheritance from Arditi et al.; the live research frontier is the kernel shape, geometric corrections (projection, norm preservation), and whether to use a direction at all (ARA).
- Heretic's design choice to let the MLP kernel go to zero, plus grimjim's norm preservation, both target the same empirical problem: MLP/magnitude edits are where capability damage concentrates.

### Gaps
- Exact compute/time figures for Abliterix and OBLITERATUS runs are largely self-reported or absent.

## Key question 2 — Datasets, chat-template handling, token position

### Takeaway
Nearly all tools use `mlabonne/harmful_behaviors` (repackaged AdvBench) as the harmful set and `mlabonne/harmless_alpaca` (or alpaca-cleaned) as the harmless set, apply the model's chat template with `add_generation_prompt=True`, and take the residual at the last token of the generation prefix. Sample counts range from 32 (Sumandora, Labonne test) to 128 (Arditi) to 256–400 (Labonne train, Heretic).

### Cited Findings
- Arditi: 128/128 train, 32/32 val; harmful from AdvBench+MaliciousInstruct+TDC2023, harmless from Alpaca; directions at all post-instruction positions — [arXiv 2406.11717](https://arxiv.org/html/2406.11717)
- Heretic: direction from `train[:400]` of harmful_behaviors / harmless_alpaca; refusal eval on `test[:100]` harmful_behaviors; KL eval on `test[:100]` harmless_alpaca; residual at position −1 of the first generated token, with the chat template applied (`add_generation_prompt=True`) and a configurable response prefix — [heretic config.default.toml](https://github.com/p-e-w/heretic/blob/master/config.default.toml), [heretic model.py](https://github.com/p-e-w/heretic/blob/master/src/heretic/model.py)
- Sumandora: 32 instructions, layer index 0.6·L, pos −1, chat template with generation prompt, 1-token generation capturing hidden states — [Sumandora compute_refusal_dir.py](https://github.com/Sumandora/remove-refusals-with-transformers)
- Labonne: n_inst_train ≤ 256/class, batch 32, pos −1, 4 test instructions — [mlabonne blog](https://huggingface.co/blog/mlabonne/abliteration)
- Chinese/CCP-sensitive extensions: jim-plus `--deccp` and grimjim add deccp topics to the "harmful" set; a Traditional-Chinese VLM card found that extracting the direction with English prompts destroyed zh-TW generation (繁中 5/8→0/8 coherent) and switched to Traditional-Chinese prompt pairs to preserve it — [jim-plus README](https://github.com/jim-plus/llm-abliteration), [Qwen3-VL-32B-Abliterated-xCloud card](https://huggingface.co/xCloudinfo/Qwen3-VL-32B-Abliterated-xCloud)

### Inferences
- Language of the extraction prompts matters: the refusal direction co-localizes with language features, so monolingual extraction can collaterally damage other languages — a recurring, under-appreciated practical lesson.

### Gaps
- No independent study systematically varies prompt count to find a saturation point; the 32→400 range is convention, not an optimized value.

## Key question 3 — MoE models (Qwen3 MoE, Mixtral, gpt-oss, DeepSeek)

### Takeaway
Refusal in MoE models is distributed across many routed experts rather than isolated in a router or a few "safety experts," though a minority of experts activate disproportionately on harmful prompts. Naive LLaMA-style scripts that match module names silently miss fused or transposed expert tensors. Tools now ablate the `down_proj` of all experts (plus attention-out), and some additionally suppress routing to high-risk experts. A frontier-scale study found refusal only comes out when attention + dense + expert writers are edited jointly.

### Cited Findings
- Heretic handles MoE by iterating every expert's down_proj: Qwen3 MoE (`layer.mlp.experts[*].down_proj`), Phi-3.5-MoE (`block_sparse_moe.experts[*].w2`), Granite MoE Hybrid (`moe.experts[*].output_linear` / `shared_mlp.output_linear`), plus hybrid/linear-attention layers (Qwen3.5 MoE GatedDeltaNet `linear_attn.out_proj`). It scans all layers because hybrid models carry different components per layer. It does not edit the router — [heretic model.py get_layer_modules](https://github.com/p-e-w/heretic/blob/master/src/heretic/model.py)
- Abliterix exposes four distinct MoE mechanisms: (1) Expert-Granular Abliteration (EGA) = norm-preserving orthogonal projection on ALL expert down_proj slices in every MoE layer, (2) expert profiling of per-expert "risk scores," (3) router-weight suppression (negative bias on safety-critical experts' routing logits), (4) fused rank-1 edit of top-N experts. Its docs state dense-only abliteration leaves "~30% of refusals routed through untouched experts" on models like Gemma-4-26B-A4B — [abliterix docs/moe.md](https://github.com/wuwangzhang1216/abliterix/blob/master/docs/moe.md)
- gpt-oss architecture-specific fixes (from the Abliterix gpt-oss-20b card): native MXFP4 experts ship as `Mxfp4GptOssExperts` whose down_proj is a packed Triton tensor and cannot be edited in place, so `Mxfp4Config(dequantize=True)` is forced; `GptOssExperts.down_proj` is stored transposed `(experts, intermediate_in, hidden_out)` with `out = act @ W` and no transpose, so shape-based axis detection silently picks the wrong branch when hidden==intermediate (both 2880); fused experts are a single Module so a naive per-module hook finds no `mlp.down_proj` and EGA early-exits. gpt-oss-20b = 24 layers, 32 experts, top-4. Winning run steered q/k/v/o + all 32×24 expert down_proj (EGA) + router suppression of top-1 safety expert/layer (router_bias −0.64); 6/100 refusals at KL 0.0098, 100 trials, ~5h20 on one RTX PRO 6000 — [wangzhang/gpt-oss-20b-abliterated card](https://huggingface.co/wangzhang/gpt-oss-20b-abliterated)
- Frontier-scale MoE study (Shi/Chen/Shen, arXiv 2609.09793, 9 Sep 2026): GLM-5.3-Flash, 320B MoE, 288 routed experts, block-FP8. Editing each module type alone removed little refusal (attention 0.039, dense 0.016, routed experts 0.148); editing all three jointly removed 0.776, and 74% of the effect appeared ONLY under joint intervention. Conventional module-name matching captured only 0.066 of 0.776. Conclusion: directional ablation "survives the architecture" up to 320B, but module-name matching "can fail silently on MoE models," and evaluating any single module type in isolation understates vulnerability. Refusal recovered did not coincide with expert routing behavior — attention plays a substantial role — [arXiv 2609.09793](https://arxiv.org/abs/2609.09793)
- SteerMoE (Fayyaz et al., arXiv 2509.09660, Sep 2025, ICLR 2026): detect behavior-linked experts by activation-frequency differences on paired safe/unsafe inputs, then toggle them at inference (no fine-tuning); steering toward unsafe experts lowered safety by 41% (up to −100% combined with jailbreaks), arguing alignment concentrates in a few expert pathways — [arXiv 2509.09660](https://arxiv.org/abs/2509.09660); GateBreaker (Wu et al. 2025) similarly reports MoE safety concentrates in a small subset of experts/neurons — [search summary](https://www.themoonlight.io/review/steering-moe-llms-via-expert-deactivation)
- Independent MoE comparison (Abliterlitics GLM-4.7-Flash, 59B MoE/64 experts, snapshot May 2026): all four tools (Heretic, HauhauCS, Huihui, Abliterix) reached 100% ASR / 0 refusals on HarmBench-400 — "64 routed experts per layer did not make safety removal harder." Heretic = 1,826 rank-1 tensors concentrated on expert down_proj + attention o_proj, best raw GSM8K, lowest empty-response rate, but largest TruthfulQA-MC2 drop (−6.80); Abliterix = 1,088 tensors targeting routers + shared experts, which "disrupts response-length behavior" → 49.2% empty-response rate on GSM8K. Cross-technique edit-vector cosine similarity 0.09–0.35 (no shared "abliteration subspace") — [Abliterlitics GLM-4.7-Flash](https://reddit.sentinel-team.org/posts/1sy18lx/snapshots/2026-05-02T03%3A06%3A21.60641Z)
- huihui-ai Qwen3-30B-A3B MoE card ships a router hook (`layer.mlp.gate`, top-8 indices) to profile which experts activate — consistent with expert-profiling practice — [huihui Qwen3-30B-A3B-2507 card](https://huggingface.co/huihui-ai/Huihui-Qwen3-30B-A3B-Instruct-2507-abliterated)

### Inferences
- Two complementary views coexist: refusal is "distributed across all experts" (so edit them all, EGA) yet a small subset is disproportionately safety-linked (so profiling/router suppression adds marginal value). In practice editing all expert down_proj is the robust default; router suppression is an optional extra that can over-disturb routing/length behavior (Abliterix's high empty rate).
- The 320B result reframes "which modules" from a name-matching problem to a joint-intervention problem — the single most important recent MoE finding for tool authors.

### Gaps
- No controlled comparison isolating router-suppression's net benefit vs its length/empty-response cost on a single model.

## Key question 4 — Reasoning / thinking models (R1 distills, Qwen3 thinking, gpt-oss)

### Takeaway
Refusal in reasoning models is jointly encoded in residual activations AND in the chain-of-thought, so activation-only ablation is less reliable than on instruction models and tends to leave "safety deliberation" inside the CoT even when the visible answer complies. Tools handle this by skipping the closed CoT block so evaluation/direction-extraction happens at the start of the real answer; the strongest effect comes from also influencing the CoT itself.

### Cited Findings
- "Where Do Reasoning Models Refuse?" (Yamaguchi, Etheridge, Arditi; arXiv 2507.03167, Jul 2025, rev. May 2026): across four reasoning models, the CoT causally influences refusal; in distilled models "subtle differences in the opening sentence of the CoT can fully determine the refusal decision." Ablating extracted directions increases harmful compliance but "less reliably than on non-reasoning models" and causes "non-negligible degradation to general capabilities" — [arXiv 2507.03167](https://arxiv.org/abs/2507.03167)
- "Beyond a Single Direction" (Yang et al., arXiv 2605.26772, May 2026, ICML 2026 MI workshop): on DeepSeek-R1-Distill-LLaMA-8B, activation steering reversed refusal in ~39% of cases with the CoT fixed, ~70% with the CoT removed (CoT reinforces refusal), ~94% when the model regenerated its CoT under steering; the regenerated CoT retained ~48% of the effect after steering was removed. Refusal is jointly encoded in activations and CoT — [arXiv 2605.26772](https://arxiv.org/abs/2605.26772)
- Harm-keyed routing study (Reblitz-Richardson, arXiv 2609.14759, Sep 2026): on OLMo-3, ~three-quarters of refusal's causal input lies outside the moral subspace; a "rank-one edit removes it," but GPT-OSS refusals "can be argued in either direction by its own reasoning trace." One linked analysis notes a standard refusal direction flipped only ~4% of gpt-oss-20b refusals on a held-out diverse set, and a direction taken from CoT tokens flipped none — i.e., no single direction ablates gpt-oss refusal on held-out prompts — [arXiv 2609.14759](https://arxiv.org/abs/2609.14759), [search summary](https://arxiv.org/pdf/2609.14759)
- Heretic CoT handling: config lists `chain_of_thought_skips` pairs so the optimizer evaluates at the start of the real answer, e.g. `<think>`→`<think></think>`, and for gpt-oss the harmony analysis channel `<|channel|>analysis<|message|>` → `<|channel|>analysis<|message|><|end|><|start|>assistant<|channel|>final<|message|>`; `[THINK]`/`<thought>` variants included. v1.1.0 added "support for thinking models." Heretic also auto-detects the response prefix by generating with a dummy prompt — [heretic config.default.toml](https://github.com/p-e-w/heretic/blob/master/config.default.toml), [heretic releases](https://github.com/p-e-w/heretic/releases)
- gpt-oss results: Heretic v1.0.0 only got gpt-oss-20b to 58/100 refusals (KL 0.96) with single-direction ablation; the ARA PR author states "one-direction ablation is not enough to get rid of the refusal reasoning on GPT-OSS" and ARA reached ~3/100 at KL ~0.12 (self-reported). Independent Abliterlitics (GLM-4.7-Flash) found that despite 100% visible ASR, all four tools still showed safety deliberation in 39–60% of CoTs (Heretic 59.2% deliberation, 7.5% explicit refusal language, 30.5% disclaimers) — [PR #211](https://github.com/p-e-w/heretic/pull/211), [Abliterlitics GLM-4.7-Flash](https://reddit.sentinel-team.org/posts/1sy18lx/snapshots/2026-05-02T03%3A06%3A21.60641Z)
- huihui DeepSeek-R1-Distill cards note a practical quirk: if `<think>` fails to appear or the model refuses, give a one-shot example first to force the thinking format — [huihui R1-Distill-Qwen-32B card](https://huggingface.co/huihui-ai/DeepSeek-R1-Distill-Qwen-32B-abliterated)
- Reasoning-model benchmark caveat (Abliterlitics): raw GSM8K is misleading because broad edits cause "overthinking" that exhausts the token budget → empty answers; must separate empty-response rate from reasoning ability (e.g. Heretic raw 89.16% / 4.9% empty / adjusted 93.75%; Abliterix raw 47.38% / 49.2% empty / adjusted 93.30%) — [Abliterlitics GLM-4.7-Flash](https://reddit.sentinel-team.org/posts/1sy18lx/snapshots/2026-05-02T03%3A06%3A21.60641Z)

### Inferences
- Best practice for reasoning models: extract/evaluate at the post-CoT answer start (skip the closed think block), accept that visible ASR overstates success (CoT may still deliberate), expand generation length in evaluation, and report empty-response-adjusted benchmarks. Direction-free methods (ARA) or CoT-regeneration approaches outperform single-direction ablation here.

### Gaps
- No public tool yet directly optimizes against CoT-internal refusal; the academic two-stage CoT-regeneration result (2605.26772) has not been productized.

## Key question 5 — Multimodal (VLM), very large models, quantization interactions

### Takeaway
VLM abliteration is almost always text-only: extract and ablate on the language tower, leave the vision tower untouched; a single direction is preferred to limit interactions with the vision stack. Very large and MoE models are handled by sharded/one-layer-in-VRAM ablation or bnb 4-bit for measurement. The universal ordering is abliterate the full-precision (or dequantized) weights first, then quantize to GGUF/etc.; native-FP4 models (gpt-oss MXFP4) must be dequantized to BF16 to edit, then optionally re-packed.

### Cited Findings
- VLMs: Heretic reads layers via `model.model.language_model.layers` for most multimodal models and saves the processor; "broad support for VL models" added v1.2.0 (#108). huihui Qwen2.5-VL card: "only the text part was processed, not the image part." sci4ai Qwen2.5-VL "Ablit" uses classic heretic-style single-direction ablation on decoder layers 1–27 + lm_head at a uniform factor, keeps the vision tower, "chose single direction for simplicity and compatibility with the vision tower." xCloud Qwen3-VL-32B ablated o_proj + mlp.down_proj on layers 50–63 (28 tensors) at strength 1.0, with Traditional-Chinese extraction prompts (English extraction destroyed zh-TW output) — [heretic model.py](https://github.com/p-e-w/heretic/blob/master/src/heretic/model.py), [huihui Qwen2.5-VL card](https://huggingface.co/huihui-ai/Qwen2.5-VL-7B-Instruct-abliterated), [sci4ai card](https://huggingface.co/sci4ai/Qwen2.5-VL-7B-Instruct-Ablit), [xCloud Qwen3-VL-32B card](https://huggingface.co/xCloudinfo/Qwen3-VL-32B-Abliterated-xCloud)
- Abliterix VLM support lists Qwen2-VL, InternVL2, LLaVA-NeXT, Pixtral, Mistral3-VL — [abliterix README](https://github.com/wuwangzhang1216/abliterix)
- Very large models: jim-plus ablates one shard/one layer at a time so huge models fit; Heretic supports `device_map="auto"`, `max_memory`, multi-GPU (v1.1.0) and bnb 4-bit; huihui published a DeepSeek-R1 671B (37B active) abliterated variant (distributed via Ollama at q2_K ≈ 148 GB file). Abliterix lists Qwen3.5-122B-A10B, Llama-4-Maverick-401B, Mixtral-8x22B, gpt-oss-120b configs (gpt-oss-120b self-reported 26/100 refusals, KL 5.4e-6) — [jim-plus README](https://github.com/jim-plus/llm-abliteration), [heretic README], [abliterix README](https://github.com/wuwangzhang1216/abliterix)
- Quantization ordering: standard GGUF releases abliterate the BF16/full model first, then imatrix-quantize (the abliterated weights are the quant's starting point). Heretic can load bnb 4-bit for the search but merging requires reloading/dequantizing the base; it keeps the ablation as a LoRA that rides on the frozen quantized base (so the quantized base stays intact and the edit is a small BF16 adapter). bnb 4-bit `quantization` option; MXFP4 loading needs PyTorch ≥2.6 (`torch.accelerator`). grimjim confirmed a direction measured on a 4-bit quant stays effective on the full BF16 model — [heretic main.py merge logic](https://github.com/p-e-w/heretic/blob/master/src/heretic/main.py), [heretic README], [grimjim projected-abliteration](https://huggingface.co/blog/grimjim/projected-abliteration)
- Native FP4: gpt-oss MXFP4 experts must be dequantized to BF16 to edit (`Mxfp4Config(dequantize=True)`); Abliterix adds `abliterix-abliterate-fp4` to re-pack back to 4-bit without a BF16 blow-up and a `frozen_experts` mode applying the rank-1 edit at forward time against packed 4-bit weights — [wangzhang gpt-oss-20b card](https://huggingface.co/wangzhang/gpt-oss-20b-abliterated), [abliterix README](https://github.com/wuwangzhang1216/abliterix)
- llama.cpp added gpt-oss GGUF conversion at build b6115; huihui gpt-oss GGUF needs Ollama ≥ v0.11.8 — [huihui gpt-oss card](https://huggingface.co/huihui-ai/Huihui-gpt-oss-20b-BF16-abliterated)

### Inferences
- Quantization is applied after abliteration in essentially all documented pipelines; there is no documented practice of abliterating a GGUF directly. The open empirical question "do refusals return after aggressive quantization" was not answered by any source found (see Gaps).
- For VLMs the conservative single-direction, text-tower-only recipe is the field norm precisely to avoid unpredictable interactions with the vision encoder.

### Gaps
- No source measured refusal-rate drift introduced by post-abliteration quantization (e.g., Q2/Q4 vs BF16). Plausible but unconfirmed.
- No public multimodal abliteration targets refusals conditioned on image inputs; all are text-side.

## Key question 6 — Practical lessons: failure modes, diagnosis, healing

### Takeaway
The recurring failure modes are: (a) incoherence/"gibberish" and capability loss from over-aggressive or MLP/magnitude-heavy edits; (b) "soft"/delayed refusals that keyword judges and short generations miss; (c) over-compliance / loss of the ability to push back; (d) degraded math/coding and reasoning "overthinking." Diagnosis has professionalized around longer generations, LLM-judge + keyword hybrid detection on held-out adversarial sets, KL thresholds, and weight forensics. The standard fix for capability loss is light DPO "healing"; the standard fix for residual refusals is band-of-layers intervention, norm preservation, or direction-free methods.

### Cited Findings
- Capability cost is intrinsic: a 2026 guide states abliteration "always costs 1–4 MMLU points" and recommends abliterate-then-DPO; Labonne's NeuralDaredevil is the canonical healing example (Nous avg 55.06 → 55.87 after one DPO epoch) — [insiderllm guide](https://insiderllm.com/guides/best-uncensored-local-llms/), [NeuralDaredevil card](https://huggingface.co/mlabonne/NeuralDaredevil-8B-abliterated)
- Evaluation is systematically gamed (Abliterix docs/evaluation.md): short 30–50-token generations miss Gemma-4's "delayed refusal" (helpful framing first, refusal later) — measured 30 tokens ~8/100, 50 tokens ~18/100, 100 tokens 60/100 (converged) on the same model; a prominent "3/100" model measured 60/100 under their pipeline. Fixes: ≥100-token generations, keyword + LLM-judge (they use a Gemini flash model) with a degenerate-output filter that counts gibberish/loops as refusals, and harder bilingual/socially-engineered prompt sets — [abliterix docs/evaluation.md](https://github.com/wuwangzhang1216/abliterix/blob/master/docs/evaluation.md)
- Comparative capability study (Young, arXiv 2512.13655, Dec 2025, 16 models 7–14B, tools Heretic/DECCP/ErisForge/FailSpy): math reasoning is the most sensitive capability — GSM8K change ranged +1.51 to −18.81 pp (−26.5% relative) depending on tool/architecture; single-pass methods preserved capability better on the benchmarked subset (ErisForge −0.28pp, DECCP −0.13pp avg GSM8K); Bayesian-optimized ablation gave variable KL 0.043–1.646 — [arXiv 2512.13655](https://arxiv.org/abs/2512.13655)
- Weight-forensics benchmark (Abliterlitics Gemma-4-E4B, 24 models, lm-eval-harness 13 tasks + HarmBench-400, KL over full 262K vocab first-token on 100 harmless): base ASR 30.8%. Best overall Heretic 95.5% ASR, GSM8K +1.3pp, 29 tensors, KL 0.0021 (pure o_proj). Zero-refusal abliterix 100% ASR, −4.4pp IFEval, KL 0.0536 (89 tensors incl q/k/o). Avoid: obliteratus KL 1.10, −20.9pp GSM8K, −11.7pp MMLU-Pro, 24 empty + 39 truncated HarmBench responses (381 tensors). Conclusions: surgical edits preserve capability; KL above ~0.3 is where damage becomes visible; IFEval is the earliest warning signal; "quality does not predict downloads" (obliteratus had ~36× the downloads of the runner-up) — [Abliterlitics Gemma-4-E4B](https://huggingface.co/DreamFast/Gemma4-e4b-abliterlitics)
- Hardest-model lesson (Abliterix): Gemma 4's double-norm (4× RMSNorm/layer) + Per-Layer Embeddings resist LoRA and hook-based steering; only direct weight editing with norm-preserving orthogonal projection in float32 across q/k/v/o + down_proj works; conservative strength ranges [0.5,2.0] give KL<0.001 but barely cut refusals — must widen to [1.0,6.0] to clear the "low-KL plateau." Discriminative layer selection was the single biggest KL reducer (−8 to −12% vs baseline) — [abliterix docs/evaluation.md](https://github.com/wuwangzhang1216/abliterix/blob/master/docs/evaluation.md)
- Over-compliance / loss of pushback: community/guide sources note abliteration removes the "machinery" of refusal rather than teaching judgment, so abliterated models can lose the ability to push back on bad assumptions and can reduce truthfulness/reliability (consistent with Arditi's consistent TruthfulQA drop) — [search summary](https://dev.to/nishilbhave/best-uncensored-llm-in-2026-pick-one-that-wont-over-refuse-c7l), [arXiv 2406.11717](https://arxiv.org/html/2406.11717)
- Incoherence diagnosis: FailSpy warns the first/last couple of layers "will have dramatic effects" and should be blacklisted; Heretic test-runs stop a batch on a negative token; grimjim's Hydra-effect lesson (refusals return if too few layers are edited) and float32-intermediate + winsorization fixes address numerical instability / massive activations — [FailSpy README](https://github.com/FailSpy/abliterator), [grimjim norm-preserving](https://huggingface.co/blog/grimjim/norm-preserving-biprojected-abliteration)
- Choosing among Optuna Pareto-optimal trials: Heretic presents the Pareto front of (refusals, KL) trials and lets the user pick, chat-test, benchmark, save or upload; lower-KL trials retain more capability at the cost of a few more refusals — [heretic README / main.py](https://github.com/p-e-w/heretic)
- Non-determinism: Abliterlitics notes Heretic is "non-deterministic across runs" (random search seed), so each abliteration is effectively a slightly different model — argues for reproducibility manifests (Heretic v1.3.0 reproducible runs; Abliterix hash-pinned manifests) — [Abliterlitics GLM-4.7-Flash](https://reddit.sentinel-team.org/posts/1sy18lx/snapshots/2026-05-02T03%3A06%3A21.60641Z), [heretic releases](https://github.com/p-e-w/heretic/releases)

### Inferences
- A concrete current workflow the writer can recommend: pick an automated tool (Heretic for broad/dense/most MoE+VLM, Abliterix if explicit router/FP4/EGA control is needed); keep defaults (harmful_behaviors/harmless_alpaca, last-token direction, attention-out primary, MLP kernel allowed→0, norm preservation on); for reasoning models enable CoT-skip and evaluate post-CoT; evaluate with ≥100-token generations + LLM-judge on a hard held-out set and watch IFEval/KL (KL<~0.3) as the damage tripwire; for MoE edit all expert down_proj, treat router suppression as optional; for FP4/MXFP4 dequantize→edit→repack; quantize to GGUF last; if math/coding regressed, apply light DPO healing (NeuralDaredevil recipe).
- Keyword-only, short-generation evaluation is the single biggest source of inflated published refusal numbers — the writer should flag that most model-card "3/100" claims are not comparable.

### Gaps
- Independent, apples-to-apples capability benchmarks across the newest tools on identical models are mostly from one community project (Abliterlitics/DreamFast) and self-reports; peer-reviewed cross-tool capability comparison is limited to arXiv 2512.13655 (older/smaller tool set).
- No source quantifies the over-compliance ("can't say no") failure mode with a metric; it is described qualitatively.
